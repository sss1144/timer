## データ構造

要件書 9 章のとおり（v3）。データベースのバージョンの移り変わり：

- v1：最初の形。
- v2：プロジェクトの色の候補を、グラフで見分けやすい 8 色（色覚の違いも含めて検証済み）に変更。以前の候補の色は近い新しい色に置き換える（`src/lib/colors.ts`）。
- v3：ブロック式タイマー。プリセットを追加し、要件書 13 章のとおり移行する（`src/db/migrations.ts`）。新しく使い始めたときは、初期のプリセット 2 つを入れる。
- v4：アラーム音を「作業終了の音」「作業開始の音」に分け、音量（初期値 70）を足す（要件書 13 章の設定の移行のうち、音の部分）。実行中のタイマーはそのまま。

## 決定事項

- カウントダウンは作らない（ブロックタイマーとストップウォッチの 2 モード）。
- ブロックタイマーの「停止」は最初のブロックの開始前に戻る（やり直し）。続きから再開したいときは「一時停止」を使う。
- 「スキップ」：開始前なら待機するブロックを次へ送るだけ（どこから始めるかを選べる）。作業ブロックの途中で 1 分未満なら確認を出さない。動いていて「自動で進む」がオンなら次のブロックをすぐ始め、そうでなければ次のブロックの開始前で待つ。「1 回だけ」の最後のブロックなら最初に戻る。
- 作業ブロックの途中で停止・スキップして「記録する」を選んだ記録は `completed = false`（画面には出さない）。
- アプリを閉じている間にブロックが終わった場合：次に開いたとき本来の終了時刻で記録する。「自動で進む」がオンでも、その次のブロックは自動で始めない。
- タイマーの実行中（一時停止中を含む）は、使っているプリセットを編集・削除できない。プリセットは最後の 1 つを削除できない。
- 選んでいたプリセットが使えない（削除済みなど）ときは、最後に使ったもの → 先頭 の順に選び直す。プリセットを選んだり開始したりすると「最後に使ったプリセット」を覚える。
- ストップウォッチの止め忘れ確認：「続ける / 確認した時点で止めて記録 / 今止めて記録」の 3 択。
- 終了時のメモ欄は画面内に出すだけで、タイマーは止めない。
- 日付の区切り時刻は日・週・月のすべての集計に使う。
- 日をまたぐ記録は分割せず、開始時刻の日にすべて数える（方針 A）。計測中の作業も同じで、タイマー画面の「今日の合計」には開始した日の分だけ含める。深夜の作業が多い場合は日付の区切りを 4 時などにする。1 日のタイムラインでは、その日の範囲からはみ出す部分を端で切って表示する。
- JSON の統合読み込みでは、設定は今の端末のものを残し、実行中のタイマーは読み込まない。
- アラーム音は音源ファイルを使わず Web Audio で生成し、2〜3 種類から選べるようにする。
- アーカイブしたプロジェクトのタスクは、タスク一覧では「アーカイブ済みも表示」をオンにしたときだけ出す。
- プロジェクトが見つからないタスク（データの不整合など）は「プロジェクトなし」として表示する。
- ストップウォッチを一時停止中に停止した場合、記録の終了時刻は一時停止した時刻にする。
- 閉じている間に終わったブロックは音を出さず、開いたときにお知らせ表示で伝える。
- 音はブロックの開始・再開の時点で予約する（`src/timer/alarm.ts`, `TimerRunner.tsx`）。「自動で進む」がオンなら、続くブロックの終わりの音も 24 時間先までまとめて予約する（画面が隠れて次のブロックへ進む処理が遅れても、音は時間どおりに鳴る）。状態が変わるたびに取り消して予約し直すが、もう鳴り始めた音は最後まで鳴らす。
- 「その場で終わった」とみなすのは、終了予定から 2 分以内に気づいたとき（通知と自動で進むの判断）。画面が隠れているとページのタイマーが最大 1 分ほど遅れるため。
- 音を予約できない（再読み込みのあとで、まだクリックやキー操作をしていない）ときは、画面上部に「クリックすると音が鳴るようになります」を出す。どこをクリックしても音が使えるようになる。
- 音の一覧は `src/timer/sounds.ts` にまとめる。ここに足すだけで設定画面で選べる。
- タスク一覧の開始ボタンは、タイマーが止まっているときだけ開始する（動いているときはタイマー画面へ移動する）。
- 記録の手動追加・編集：終了が開始以前なら翌日の時刻とみなす。1 件は 24 時間まで。作業時間は開始〜終了の長さ以下。
- 一時停止のない記録（作業時間 = 開始〜終了）は、時刻を変えると作業時間も合わせて変わり、作業時間を変えると終了時刻が変わる。一時停止のある記録は時刻と作業時間を別々に直す。
- 編集で時刻や作業時間に触れなければ、秒まで元の値を保つ（メモだけ直しても時刻がずれない）。
- 時間が重なる記録は、入力中に警告し、記録一覧でも「時間が重なっています」と表示する。ちょうど続く記録（終了 = 次の開始）は重なりとしない。
- 統計：週・月は「日ごとの推移」（プロジェクトの色で積み上げた縦棒）、日・週は「作業した時間帯」（タイムライン）を表示する。月のタイムラインは出さない。
- 統計の色分けはプロジェクト単位。未分類・プロジェクトなし・削除済みタスクは灰色。プロジェクトが 9 個以上ある期間は、推移グラフでは時間の少ないものを「その他」にまとめる（色を使い回さない）。
- 削除済みタスクの記録は、そのタスクのプロジェクトに数える。タスク別の一覧では「削除済みタスク」1 行にまとめる。
- 完了タスク数は、完了した日時（doneAt）がその期間に入るタスクの数。
- 作業時間のタイルに、前の期間との差を表示する。1 日あたりは、今の期間なら今日までの日数で割る。
- グラフは棒をタップ（マウスなら乗せる）すると内訳を表示し、「この日を見る」で日の表示に移る。色だけに頼らないよう、凡例と「表で見る」を付ける。
- 繰り返しタスク（毎日）：タスクの入力画面の「毎日繰り返す」で切り替える。オンにすると 1 日の予定時間（初期値 60 分）を入れ、見積もり時間と期限は消える。
- 今日の予定に出すのは、未完了・削除済みでない繰り返しタスクのうち、アーカイブしたプロジェクトに入っていないもの（作成順）。タスク一覧の「毎日のタスク」は、絞り込みと「アーカイブ済みも表示」に従う。
- 今日の実績に計測中の時間を足すのは、今日に開始した作業だけ（記録と同じく開始した日に数える）。ブロックタイマーの休憩中は増えない。
- 達成の印は「✓ 達成」の文字で出す（色だけに頼らない）。
- スペースキー：入力欄・ボタン・リンクなどにフォーカスがあるとき、ダイアログを開いているとき、Ctrl などと一緒に押したときは効かない（ボタンにフォーカスがあるときはボタンそのものが押される）。
- 書き出す JSON は `{ app: "work-timer", version: 3, exportedAt, data: { projects, tasks, sessions, presets, settings } }`。削除済みの印が付いたものも含める。実行中のタイマーとバックアップ先のフォルダは含めない（`src/backup/format.ts`）。
- CSV の「日付」は、その記録を数える日（日付の区切り時刻で決める日）。「分」は小数第 1 位まで。ファイル名は `worklog-開始日_終了日.csv`。
- Markdown の時間は要件書の例に合わせて「（75分）」のように分で書く。合計は「2時間10分」の形。ファイル名は `worklog-日付.md`。
- 復元の前に書き出すファイルは `worklog-before-restore-日付-時分.json`。復元したデータにプリセットが 1 つもなければ、初期のプリセットを足す。
- 自動バックアップ：中身（最後にバックアップした日時を除く）が前回と同じで、同じ日のファイルがあれば書き直さない。フォルダの情報と状態は `kv` の `backupDir`・`backupState` に置く（`src/backup/auto.ts`）。
- 書き出しを促す案内は、自動バックアップを設定していないときだけ。一度も書き出していない場合は、いちばん古い記録の日から 7 日で出す。
- iPhone・iPad の Safari で開いたときは「ホーム画面に追加」を案内する（閉じると再表示しない）。
